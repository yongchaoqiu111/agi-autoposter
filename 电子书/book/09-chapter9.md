# 第 9 章 幻觉的层层过滤

---

## 9.1 幻觉的本质

大模型的幻觉不是 bug，是特性。

它会编造：

- 不存在的事实
- 不存在的指令
- 不存在的状态
- 不存在的接口参数

现有框架试图"减少"幻觉，但没有任何框架能"消除"幻觉。

这套架构的思路不是"减少幻觉"，而是**"不让幻觉逃逸"**。

---

## 9.2 四层过滤机制

### 第一层：内容层过滤

**不给编造空间。**

内容层不输出"内容"，只输出"内容 ID"。

大模型看不到完整文案，只能看到 content_id=5。它无法编造内容，因为内容根本不在它的上下文里。

**过滤效果：大模型无法编造新内容。**

### 第二层：调度层过滤

**不给幻觉机会。**

调度层只允许从白名单中选择：

- 平台白名单：[douyin, facebook, tiktok, x, instagram]
- 文案 ID 白名单：[1,2,3,4,5]
- 图片 ID 白名单：[1,2,3,4,5]

大模型如果"幻想"出一个不存在的平台（比如 douyin2），调度层会直接拒绝。

**过滤效果：大模型的幻觉被限制在"选哪个 ID"，而不是"编造什么指令"。**

### 第三层：执行层过滤

**不信任任何输入。**

执行层不假设参数是合法的。它会：

- 校验参数格式（--platform 必须是白名单内的）
- 校验参数范围（--txtid 必须在 1-100 之间）
- 拒绝非法输入，返回错误信息

**过滤效果：即使调度层不小心传了非法参数，执行层也会拦截。**

### 第四层：监督层过滤

**阻断异常传播。**

如果一个任务失败了，监督层会记录原因。但它不会让失败"传染"到其他任务。

- 失败任务不会自动重试无限次（有次数上限）
- 失败任务不影响队列中的其他任务
- 失败信息会被记录，但不会被传播到其他原子

**过滤效果：异常被隔离，不会扩散。**

---

## 9.3 四层过滤的完整链路

```text
大模型生成指令
    │
    ▼
┌─────────────────────────────────────────┐
│ 第一层：内容层                           │
│ 大模型只能看到 content_id，看不到内容    │
│ → 无法编造新内容                         │
└─────────────────────────────────────────┘
    │
    ▼
─────────────────────────────────────────┐
│ 第二层：调度层                           │
│ 大模型只能从白名单中选择                  │
│ → 无法编造不存在的平台/ID                 │
└─────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────┐
│ 第三层：执行层                           │
│ 执行层校验参数合法性                      │
│ → 非法参数被拒绝                         │
─────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────┐
│ 第四层：监督层                           │
│ 失败被隔离，不扩散                        │
│ → 异常不会传染                           │
└─────────────────────────────────────────┘
    │
    ▼
  真实世界（安全）
```

## 9.4 与传统方案的对比

| 方案 | 处理方式 | 效果 |
|------|---------|------|
| 传统 Agent | 试图让大模型"不幻觉" | 无法根治 |
| MCP 协议 | 无过滤 | 幻觉可能直接执行 |
| 本架构 | 四层过滤，层层拦截 | 幻觉被隔离，无法逃逸 |

---

## 9.5 为什么这套过滤机制有效

因为它的设计原则是：

> **不信任大模型。**

- 内容层不信任大模型会"正确选择内容"，所以只给它 ID
- 调度层不信任大模型会"正确选择参数"，所以只允许白名单
- 执行层不信任调度层会"传对参数"，所以自己校验
- 监督层不信任任何环节，所以记录一切

**信任是逐层递减的，校验是逐层递增的。**

---

## 9.6 真实案例：幻觉如何被过滤

假设大模型"幻想"出以下指令：

```text
platform: "douyin2"  # 不存在的平台
txt_id: 999          # 不存在的内容 ID
```

- **第一层（内容层）**：大模型只看到 content_id 列表，无法编造 999，因为 999 不在列表里。
- **第二层（调度层）**：douyin2 不在平台白名单，调度层直接拒绝，返回错误。
- **第三层（执行层）**：根本没机会执行。
- **第四层（监督层）**：记录这次失败，标记为"非法平台"，供后续分析。

**结果：幻觉被拦截，没有到达真实世界。**

## 本章小结

| 过滤层 | 职责 | 效果 |
|--------|------|------|
| 内容层 | 只输出 ID | 无法编造新内容 |
| 调度层 | 白名单选择 | 无法编造不存在的平台/ID |
| 执行层 | 参数校验 | 非法参数被拒绝 |
| 监督层 | 隔离异常 | 异常不会传染 |

**四层过滤，层层拦截，幻觉无处可逃。**
